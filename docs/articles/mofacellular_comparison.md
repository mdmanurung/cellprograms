# Historical comparison: local-first and joint multicellular factors

**Historical recipe, not a newly executed comparator benchmark.** Code is display-only during documentation builds. The retained numerical narrative and cached objects have not been regenerated under the current source/units/fairness contract; they cannot certify calibration or comparative advantage. Current study execution and support status belong to cellprograms-reproducibility.

<a href="https://saezlab.github.io/MOFAcellulaR/" class="external-link">MOFAcellulaR</a> fits a **joint** multicellular factor analysis: the pseudobulk profiles of all cell types are stacked as MOFA2 views (one per cell type), and MOFA estimates a single latent space shared across views. Each factor is by construction a *multicellular* program — a linear combination of gene weights from every cell type.

`cellprograms` takes the **local-first** route: one empirical-Bayes matrix factorization per cell type, with cross-cell-type coordination (CMPs) and sharing (mashr) as separate, explicitly tested post-hoc questions.

This vignette preserves the old recipe for comparing both on the **same simulated data with known ground truth**. Its historical descriptions are not new results or a prespecified fair-comparison certificate. It complements the <a href="https://saezlab.github.io/MOFAcellulaR/articles/get-started.html" class="external-link">MOFAcellulaR get-started tutorial</a> and the <a href="https://liana.readthedocs.io/en/stable/tutorials/notebooks/mofacellular.html" class="external-link">liana notebook</a> on metadata associations — the same questions, asked of both models.

## The data: planted multicellular programs<a href="#the-data-planted-multicellular-programs" class="anchor" aria-label="anchor"></a>

`simulate_pseudobulk(scenario = "mixed")` plants three kinds of structure whose donor scores and gene sets are known exactly:

- **`global_IFN`** — coordinated donor activity across B, CD4, NK and Mono (the *same* donor score vector planted in each cell type) with **different genes in each cell type**. A pure activity-coordination program: gene overlap carries no signal.
- **`CD8NK_shared`** — coordinated activity *and* identical genes across CD8 and NK.
- **Private programs** (`B_private`, `Mono_private`) — single-cell-type decoys that should *not* be called multicellular.

Only one CMP is called — why not the planted CD8–NK pair? Both local fits *did* recover it (CD8_1 and NK_1 correlate r \> 0.99 with the planted donor scores), but the default ambient guard (`ambient = "drop"`, threshold 0.3) removed both members before testing: their loadings look like they track genes more highly expressed in B cells (ambient scores 0.45 and 0.39). On simulated data there is no ambient RNA by construction, so these are false positives of the guard. Re-running with `ambient = "flag"` (flag, don’t drop) recovers both planted CMPs exactly — and the CD8–NK edge turns out to be the strongest edge in the entire analysis:

## Coordination: explicit test vs by construction<a href="#coordination-explicit-test-vs-by-construction" class="anchor" aria-label="anchor"></a>

- In MOFA2, every factor is multicellular by construction; deciding *whether* a factor genuinely coordinates cell types (vs being driven by one view) is left to downstream inspection (variance decomposition per view, `plot_MOFA_hmap`).
- [`find_coordinated_programs()`](../reference/find_coordinated_programs.html) tests each candidate against a within-strata fixed-input permutation null with max-T-adjusted node p-values and reports candidate memberships. Validity requires the declared exchangeability/null assumptions; learned-factor, edge and CMP-set error control is not established.

On this data, with the ambient guard set to flag rather than drop, cellprograms recovers both planted multicellular programs exactly — membership, sign, and historical adjusted per-program p-values (all node p = 0.001) — and correctly leaves both private decoys uncalled (node p = 1). MOFA2 recovers the planted donor activity in its factors but offers no calibrated answer to “is this factor genuinely multicellular?”: every factor is multicellular by construction, so the private decoys also come back as factors with weights in every view.

The default run above illustrates the flip side of the local-first philosophy’s explicit guards: the ambient filter, doing its job on a signal it cannot verify, silently removed a true shared program. The guard is inspectable (the result’s `ambient` element) and configurable (`ambient = "flag"`), which is why flagging is the recommended setting when contamination status is unknown. MOFA2 has no analogous guard — and no analogous false positive; its risks sit elsewhere (view-dominant factors, no FWER control on “is this shared?”).

</div>

## When to use which<a href="#when-to-use-which" class="anchor" aria-label="anchor"></a>

| Question | cellprograms | MOFAcellulaR |
|----|----|----|
| Programs within one cell type | per-cell-type EBMF, sparse point-Laplace loadings | factor weights per view (shared latent space) |
| Cross-cell-type coordination | fixed-input node p-values; edge/set error control unestablished | inspect native per-view structure |
| Shared gene effects | descriptive mashr sharing labels, not equal-effect tests | native joint factor loadings; not an equivalent sharing test |
| Artifact handling | V(D)J/genotype masking + flagging | manual gene veto (`filt_gex_bybckgrnd`) |
| Variance decomposition | per-program PVE per cell type | per-factor, per-view R2 (built in) |
| Uncertainty | native posterior summaries with estimator-specific limitations | native/model-specific; not automatically comparable |
| Fit philosophy | local-first; integrate only what replicates | joint from the start |

The two are complementary: [`as_mofacellular_input()`](../reference/as_mofacellular_input.html) exists precisely so the same pseudobulk can be pushed through both, with [`align_programs()`](../reference/align_programs.html) quantifying program-to-factor geometry when both are fit.
